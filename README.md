# test-tracer

netlab-based **network scenario runner**.

Implements the plan in [`plan.md`](plan.md): it treats **netlab** as the
*Topology Provider* (builds complex multi-node topologies and applies native
`tc` link impairment) and **Ansible** as the *Test Engine* (drives
`tcpdump` captures and traffic-generation playbooks against the inventory
netlab generates), then harvests PCAPs and tears the lab down.

Lifecycle: **Create → TC → Verify → Capture/Scripts → Harvest → Teardown**.

## Why not Molecule?

Molecule tests Ansible roles against *single* containers; it has no topology
abstraction. Here netlab builds the whole network (routers, switches,
MongoDB servers, BitTorrent peers, tc-impaired links) and produces a
standard Ansible inventory (`hosts.yml`). The scenario runner simply
orchestrates: start lab → wait → capture + traffic → fetch PCAPs → destroy
lab.

## Setup

```bash
uv sync                 # installs networklab, ansible-core, pyyaml
which netlab            # provided by the networklab dependency
```

You also need a working virtualization provider on the host. The default
provider for this repo's example is **containerlab (clab)** — see
`netlab show providers`.

## Usage

```bash
# Full lifecycle on the bundled example topology
scenario -t example/topology.yml -p clab

# Preview what would run (no containers, no ansible)
scenario -t example/topology.yml -p clab --dry-run

# Only bring the lab up (leave it running)
scenario -t example/topology.yml -p clab --phase create --keep-lab

# Re-run just traffic + capture + harvest against a running lab
scenario -t example/topology.yml -p clab --phase capture,harvest

# Skip the netlab validate connectivity check
scenario -t example/topology.yml -p clab --no-validate
```

`scenario` is the console command installed into the venv;
`python main.py <same args>` works too.

Options:

| flag | description |
| --- | --- |
| `-t, --topology FILE` | netlab topology file (default `topology.yml`) |
| `-p, --provider NAME` | provider override (`clab`, `libvirt`, `vagrant`, …) |
| `--phase LIST` | comma-separated subset: `create,verify,capture,harvest,teardown` |
| `--dry-run` | print commands, execute nothing |
| `--keep-lab` | skip teardown |
| `--no-validate` | skip `netlab validate` |
| `--up-arg ARG` | extra arg passed to `netlab up` (repeatable) |

## Topology schema

The network part is plain netlab. Add a `scenario:` block to describe the
test, and declare it as a custom global attribute so netlab's attribute
validation accepts it:

```yaml
defaults:
  attributes:
    global:
      scenario: { type: dict }     # required — otherwise netlab rejects the block

scenario:
  name: mongodb_bittorrent_test
  results: results                 # where PCAPs are harvested (relative to lab dir)
  verify:
    - wait: 30                     # seconds to wait for routing convergence
  capture:
    - node: mongo1
      interface: eth1
      filter: "port 27017"
      output: mongo_sync.pcap
      # seconds: 60                # optional bounded capture
  scripts:
    - playbook: mongo_sync.yml     # ansible playbook, relative to the lab dir
      wait_after: 10               # sleep after this step
    - command: "curl -s http://10.1.0.2:8080/ping"   # or a raw controller command
```

Notes:

* **TC is native.** Put `tc: { delay: 50, loss: 2 }` on a link in the
  topology; `netlab up` applies it automatically (`providers.execute_tc_commands`).
  For complex netem setups you can also add tc commands inside a `scripts`
  playbook and run them on the nodes over SSH.
* **Capture interface names** are resolved against
  `host_vars/<node>/topology.json` (generated by netlab), so you can use the
  logical interface name from the topology (e.g. `eth1`).
* **Playbooks** run from the lab directory, so netlab's `ansible.cfg` and
  `hosts.yml` are picked up automatically. Refer to nodes by their netlab
  node names (`hosts: mongo1`).

## What gets generated

In the lab directory (where the topology file lives):

```
netlab.scenario.topology.yml   # normalized copy (scenario attr declared) — netlab up input
scenario-<name>/               # generated ansible playbooks
  scenario_capture_start.yml
  scenario_capture_stop.yml
  scenario_fetch.yml
results/                       # harvested PCAPs
hosts.yml ansible.cfg ...      # netlab's own outputs
```

## Project layout

```
test_tracer/
  cli.py        # argparse entry point (`scenario`)
  runner.py     # lifecycle orchestrator (drives netlab CLI + ansible-playbook)
  scenario.py   # topology/scenario: block parsing & validation
  playbooks.py  # generates capture/stop/fetch ansible playbooks
  console.py    # colored logging
example/
  topology.yml          # example scenario topology
  playbooks/            # example traffic generators
plan.md                 # original design document
netlab/                 # reference checkout of ipspace/netlab (not a dependency)
```

## Testing

```bash
uv sync
uv run python -c "from test_tracer.cli import main; main(['--help'])"
# dry-run of the full lifecycle (safe: executes nothing)
uv run scenario -t example/topology.yml -p clab --dry-run
```

A full end-to-end run requires a host with Docker + containerlab and the
device images pulled (`netlab up` pulls them on first use).
